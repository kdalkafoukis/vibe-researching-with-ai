A hands-on guide to the paper “Amplifying Determinant Sums”

Hamiltonicity in 1.633n

How a quantum computer could decide whether a graph has a Hamiltonian cycle in about 1.633n steps, below the best classical algorithm. Nine steps, each with something to play with.

2nBellman, Held and Karp, 1962. The textbook bound for fifty years.
1.657nBjörklund, 2010. Determinant sums with a random split.
1.633nThis paper. Björklund’s test plus amplitude amplification.

Step 1

The puzzle

A Hamiltonian cycle visits every vertex of a graph exactly once and returns to where it started. A Hamiltonian path does the same without returning. Deciding whether one exists is NP-complete, so nobody expects an algorithm that is fast on every graph. The real question is how slowly the best algorithm grows as the graph gets bigger.

Try it by hand first. Click a vertex to start, then click neighbours one at a time.

Paths and cycles are the same problem in disguise. Add one new vertex joined to every other vertex. The new graph has a Hamiltonian cycle exactly when the old one has a Hamiltonian path. So the rest of this page talks about cycles.

Step 2

How fast is fast

Every exact algorithm for this problem takes exponential time. What separates them is the base of the exponential: 2n, 1.657n, 1.633n. The chart counts steps and ignores polynomial factors, which is what the O* notation in the paper does.

Dotted lines are brute force: try every ordering of the vertices, or search those orderings with Grover’s quantum search. Both lose to plain 2n almost at once.

The step from 1.657 to 1.633 looks tiny, and in practice it buys a few vertices. It compounds, though. The ratio (1.657/1.633)n is about 4 at n = 100 and about 80 at n = 300. In complexity theory, any drop in the base counts, because nobody had a general-graph algorithm, classical or quantum, below 1.657 at all.

Step 3

A normal sieve

Searching for a Hamiltonian cycle is hard. Counting things that include all the Hamiltonian cycles can be easy, if you can make everything else cancel. That is the idea of a sieve, also called inclusion–exclusion.

Closed walks of length n are easy to count: raise the adjacency matrix to the power n and add up the diagonal. Some of these walks visit every vertex. Those are exactly the Hamiltonian cycles, counted once for each starting point and direction. The others repeat a vertex and miss another.

To keep only the walks that visit everything, count walks inside every subset of the vertices. Add the count when an even number of vertices was left out and subtract it when an odd number was. You are in control here. Play the sieve or add one tile at a time. Draw your own walk to see where it gets counted. Click a tile to see what it holds. Or edit the graph and predict the total before you press Play.

That is the normal sieve, known since the late 1970s (Kohn, Gottlieb and Kohn; Karp; Bax). It has 2n terms, each one easy, and it needs only a little memory. Its running time matches the 2n of dynamic programming. To go below 2n, you need a sieve with fewer terms.

Step 4

Cancelling in pairs

Björklund’s first idea is to replace walks with cycle covers. A cycle cover picks one outgoing arc at every vertex so that every vertex is also entered exactly once. The result is a set of separate cycles that together cover the whole graph. A Hamiltonian cycle is a cycle cover with a single cycle.

Adding up all cycle covers is easy: it is a determinant, which takes polynomial time. So Björklund gives every edge a random number as its weight and arranges for every cover with more than one cycle to meet a twin of exactly the same weight. He does the arithmetic in a number system where 1 + 1 = 0, as in XOR, so each pair of twins adds up to zero. Pick a vertex s. The twin is made by reversing a cycle that avoids s.

Labels fix the 2-cycles, but now every label must be used exactly once, and checking that takes a sieve. Step 5 is about keeping that sieve small.

Step 5

The narrow sieve

This is the trick that beats 2n. Split the vertices at random into two halves, V1 (filled) and V2 (hollow). Björklund builds his cycle covers on V1 only. Each arc of such a cover is either a path through some vertices of V2, labelled by those vertices, or a single edge between two V1 vertices. The paper calls that a direct arc and gives it one extra label.

The algorithm runs on any graph and never sees where a Hamiltonian cycle is. The pictures below show one random graph. Its Hamiltonian cycle is drawn as the outer ring, and its other edges are the faint lines inside. The split is a split of all the vertices, but whether a test can catch the cycle depends only on how the split cuts that cycle. So the odds are the same for every graph that has a Hamiltonian cycle. If a graph has several, the test needs to catch only one, so the odds can only improve. The other edges still matter for the sum, but the extra cycle covers they create cancel out, as in step 4.

The determinant already makes sure every V1 vertex is used once. The sieve only has to check the labels: n/2 vertices of V2 plus m extra labels for the direct arcs. That is 2n/2+m terms instead of 2n. This is what narrow means: inclusion–exclusion over a small set of labels, not over every vertex. The name comes from Björklund, Husfeldt, Kaski and Koivisto, who used the same idea for long paths.

There is a catch. A test with cutoff mmax only catches the cycle when the random split gives it at most mmax direct arcs. A small cutoff makes the test cheap but that event rare.

So Björklund repeats the test with fresh random splits and fresh random numbers until one fires. Each test also has a small chance that the random numbers hide a real cycle (at most 1 in 4), which repetition covers too. If the graph has no Hamiltonian cycle, no split and no random numbers can make the test fire. The error is one-sided, and that matters in step 6.

Step 6

Repeat or amplify

If one test fires with probability P, a classical computer needs about 1/P tests. A quantum computer can use amplitude amplification, the general form of Grover’s search, and needs only about 1/√P rounds. Each round runs the test once forwards and once backwards, so it costs about two tests.

The quantum computer runs Björklund’s test on a superposition of every random split and every choice of random numbers at once. A flag marks the branches where the test fired. The picture below is exact: the state lives in a plane spanned by “test fired” and “test did not fire”, and each round is two reflections that together turn it by the same small angle.

Two things make this legitimate. First, the test never fires wrongly, so a “yes” always means a real cycle. Tick the box above: with no Hamiltonian cycle the arrow starts flat and never moves. Second, the amplification is over the random choices, not over the sum inside a test. A sum needs every one of its terms. Grover can find a needle, but it cannot add up a haystack faster. So the 2n/2+m terms stay, and only the number of repetitions shrinks.

Since P is not known in advance, the algorithm uses the randomised round counts of Brassard, Høyer, Mosca and Tapp. That changes only constant factors.

Step 7

Moving the cutoff

This is the paper’s actual contribution. Once repetitions are cheaper, the best cutoff changes.

Raising the cutoff by one adds a label and doubles the cost of a test. It also makes success more likely. Classically, the extra label pays for itself while it makes success more than 2× likelier. Quantumly, the repetitions shrink only by the square root, so it pays only while success gets more than 4× likelier. The 4× point comes sooner. The quantum algorithm stops at m = n/6 instead of 0.207n, and runs cheaper tests more often.

The whole algorithm

  1. Put every balanced split of the vertices, and every choice of random numbers, into superposition.
  2. For each cutoff m from 0 to n/6, run Björklund’s narrow sieve as a reversible circuit: 2n/2+m determinants, added into an accumulator.
  3. Set a flag if any of the sums is nonzero.
  4. Amplify the flag with about 20.041n rounds. Total: 2(2/3)n · 20.041n = (8/3)n/2 ≈ 1.633n.

Memory stays small. The qubits hold the split, the random numbers and a polynomial workspace. There is no quantum RAM, which the earlier 1.728n quantum algorithm needed.

Step 9

What is proved, and what is not

  • Proved, from published lemmas. The running time follows from Björklund’s Lemmas 9–11 and the amplitude amplification theorem. The paper uses Björklund’s lemmas as published and does not re-prove them.
  • Tested end to end. The repository’s test scripts run Björklund’s test on every split of small graphs: 18,688 cases with up to 12 vertices, including the Petersen graph, with no failures. Tests on small graphs are not a proof.
  • Novelty is open. Amplifying a randomized algorithm is a standard technique, so experts may already know this observation.
  • Not the fastest everywhere. On graphs where every vertex has at most 3 or 4 neighbours, quantum backtracking (Moylett, Linden and Montanaro) is much faster: 1.110n and 1.301n.
  • Not practical. Running it would need a large fault-tolerant quantum computer, and the circuit depth is exponential, as for any exponential-time algorithm.
  • Consistent with the Exponential Time Hypothesis. The base drops, but the growth is still exponential.
